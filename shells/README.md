# 三種入口格式的骨架

12/12 主辦方會從這三種**指定一種**入口格式（規範一）。後端要用什麼技術、要不要搭配其他輔助形式，都可以自行決定。
所以這裡的三個骨架都只負責「介面」，真正的事情（LLM、評測、資料包）都交給同一個本機後端 `server/app.py`。

```
   VS Code 擴充套件 ─┐
   Chrome 外掛程式 ──┼──▶  本機後端（127.0.0.1:8787）──▶  LLM／評測／資料包
   Web 應用程式 ─────┘        API key 只放在這裡
```

| 骨架 | 怎麼跑 | 示範的功能 |
|---|---|---|
| [`web-app/`](web-app/) | `python server/app.py`，用瀏覽器開啟 http://127.0.0.1:8787 | 瀏覽資料包、看提交紀錄、AI 給一層提示、用範例測資跑程式 |
| [`chrome-extension/`](chrome-extension/) | Chrome →「擴充功能」→ 開發人員模式 →「載入未封裝項目」 | 在 Codeforces 題目頁做 60 秒反思，AI 整理成洞見卡 |
| [`vscode-extension/`](vscode-extension/) | 用 VS Code 開啟這個資料夾，按 F5（第一次先看該資料夾的 README） | AI 分析目前的程式碼、用範例測資跑目前的檔案 |

三個骨架都**不需要 npm install、不需要編譯**，改完重新整理（或重新載入擴充功能）就能看到結果。

## 每個骨架都做到四件事

1. 一行指令就能跑起來。
2. 讀一筆資料包的資料（題目、提交或歷程）。
3. 呼叫一次 LLM，輸出是固定格式、經過程式檢查的 JSON；沒有 API key 也能跑（dry-run）。
4. 出錯時不會掛掉：顯示等待時間、錯誤訊息，可以再試一次。每個骨架都有「練習出錯處理」的選項。

這也正是投影片上的四項自我檢查的前兩項。

## 建議：賽前三種都先跑過一次

12/12 才知道指定哪一種，當天不要把時間花在「第一次建專案」。賽前至少把三個骨架都跑起來，確定你的電腦環境沒問題。

想換成 React、TypeScript 或其他框架完全沒問題；換的時候記得：
- 前端不要放 API key。
- Web 開發伺服器（例如 Vite 的 http://localhost:5173）要加進 `.env` 的 `ALLOWED_ORIGINS`。
